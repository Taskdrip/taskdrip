What CourseBridge LearnpressWOO Connector does

CourseBridge links the products you sell in WooCommerce to courses hosted in LearnPress. After WooCommerce confirms payment, it enrolls the account-holding buyer in each mapped course. Administrators can also enroll users directly, review access, and manage consent-based email campaigns.

Sell a course

Connect a WooCommerce product to one or more LearnPress courses.

Grant access

Enroll buyers after payment, or assign a course to a WordPress user.

Support students

Show start links in My Account and manage course-related contacts.

Product requirements

  • WordPress 6.2 or later is the generated package’s declared minimum; PHP 7.4 or later.
  • WooCommerce and LearnPress must be installed and active.
  • Mapped-course purchases require a WordPress account; checkout can prompt account creation.
  • The current Pro edition is marked as requiring an active Taskdrip license.

Who uses each area?

  • Store / course administrator: product mappings, user assignments, contacts, settings.
  • Student: course start links in WooCommerce My Account and LearnPress profile.
  • Email recipient: can receive campaigns only when consent is recorded; unsubscribe remains available.
Read this before submitting to WordPress.org The current edition described by the source is a complete paid, license-required package. Do not submit that package unchanged as a paid-only directory download. The project’s release model calls for a useful free core in the directory and a separate premium add-on. WordPress.org makes the final eligibility and approval decision.

02 · THE WORKFLOW

From paid order to course start

The integration is a bridge between two records: the WooCommerce order and the LearnPress course enrollment.

1 · MapChoose a product and one or more courses.
→
2 · PayWooCommerce reports a successful payment.
→
3 · EnrollThe buyer account is enrolled in mapped courses.
→
4 · StartStudent opens a course from My Account or LearnPress.

Purchase-based access

CourseBridge listens for successful WooCommerce payment/order events. Orders that have not been paid do not grant access. When an administrator saves a product mapping, the plugin also schedules a check of existing paid orders for that product.

Administrator-assigned access

An administrator searches for a WordPress user, selects a LearnPress course, and optionally enters an expiry date. This direct assignment does not create or change a WooCommerce order.

One product can grant several courses Use a bundle product to map multiple LearnPress courses. The customer needs one WordPress account; CourseBridge enrolls that account in each selected course after confirmed payment.

What remains in its original system

  • Products and orders stay in WooCommerce.
  • Course content, course status, and learner progress stay in LearnPress.
  • CourseBridge stores its access records, contact/order index, consent metadata, and campaign delivery logs in the WordPress site.
  • Deactivating the plugin does not delete WooCommerce orders or LearnPress enrollments. Back up before uninstalling or changing the data model.
Test a complete checkout on staging Confirm the order reaches a paid state, the correct user is enrolled in every mapped course, and the student can start it. Do this before a real course launch.

03 · INSTALLATION

Install and prepare your site

Use a staging site first. For the paid build, obtain the ZIP from the authorized publisher and confirm its license and update terms before activating it.

1

Check the foundation

Update WordPress, PHP, WooCommerce, and LearnPress. Confirm both required plugins are active and course/product test data exists.

2

Install the plugin package

In WordPress, open Plugins → Add New Plugin → Upload Plugin, select the authorized ZIP, install, and activate. Keep a restorable backup available.

3

Confirm dependencies and license

Resolve any dependency notice. For the generated Pro edition, activate the Taskdrip license using the license workflow supplied with the purchase. The directory edition must be packaged separately.

4

Link a test product

Open CourseBridge LearnpressWOO Connector → Course Assignments, choose a published WooCommerce product, select one or more LearnPress courses, and save the mapping.

5

Place a controlled test order

Use a test gateway or low-value staging product. Create or sign in to a WordPress account, complete payment, and verify the resulting order and enrollment.

6

Check the student journey

Sign in as the test student. Check WooCommerce My Account and the LearnPress profile, then open the course start link.

7

Configure email only if needed

Choose the email provider, set the sender, and send an operational test message before collecting marketing opt-ins or sending a campaign.

Do not test on a live customer list Use a staging database and test addresses. Never send a test campaign to real customers simply to check configuration.

05 · PAYMENT BEHAVIOR

Understand when enrollment happens

CourseBridge uses WooCommerce payment/order events; it does not treat a checkout attempt as proof of payment.

Confirmed payment

When WooCommerce reports a successful payment or the order enters a paid processing/completed state, CourseBridge attempts to enroll the buyer account in mapped courses.

Awaiting, failed, or cancelled order

An unpaid order does not grant purchase-based course access. Follow WooCommerce’s payment status and gateway records when investigating a missing enrollment.

Account requirement

Mapped course products require an account. The checkout integration can enable or require account registration when a mapped course product is in the cart. The student’s account is the identity LearnPress uses for enrollment and course access.

Existing orders after mapping changes

After a mapping is saved, CourseBridge schedules reconciliation of existing paid orders for that product. This supports sites that map products after initial sales or change mappings later. Allow the scheduled work to run, then verify the target users and courses.

Changing a live mapping can affect prior buyers Before adding or removing a course from a product, decide how historical purchasers should be treated. Test on staging and review reconciled enrollments before announcing the change.

Order-to-enrollment checks

  • Correct product is in the paid order.
  • Product has the intended course mapping.
  • Customer is attached to a WordPress account.
  • WooCommerce order is paid/processing/completed.
  • LearnPress is active and the course exists.
  • Open the customer’s LearnPress profile or course access table.
  • Check for an existing enrollment or recent status change.
  • Do not manually edit plugin tables as a first fix.

Purchase-based expiry is not presented as a configurable product setting in the generated package. Optional expiry dates are available for administrator-managed course access; see the next page.

09 · CONSENT

Keep marketing permission separate

CourseBridge is designed to preserve the customer’s recorded marketing preference. An order, course enrollment, or account alone does not make a person campaign-eligible.

Checkout choiceCustomer may select the optional marketing opt-in.
→
Payment confirmedThe recorded order choice is applied to the account after successful payment.
→
Campaign eligibleOnly contacts with recorded opt-in can be selected and sent.

Administrator opt-in tools

  • Record opt-in for a purchaser from Contacts & Campaigns when the person has explicitly agreed through a valid channel.
  • Use filtered selections to record opt-in for selected purchasers across pages, or all matching purchasers, with an explicit confirmation step.
  • The bulk administrator action is for purchasers; it must not be used to infer consent from course enrollment, account creation, or an old order alone.
  • Campaigns continue to exclude contacts without recorded opt-in, even if an admin selects a wider audience.
Unsubscribe takes priority Every marketing campaign includes an unsubscribe link. Earlier paid orders do not reverse an unsubscribe. Record a new opt-in only after the person has clearly opted in again.

Good operating practice

  • Keep the checkout checkbox optional and clearly worded.
  • Explain the type and frequency of course messages.
  • Document the source/date for any manually recorded permission in your own records.
  • Filter to the relevant course/product before selecting recipients.
  • Review the eligible recipient count before sending.
  • Use a test email first; never treat a test as consent.

This guide describes plugin behavior, not legal advice. The site owner is responsible for privacy notices, lawful basis, retention, and applicable email-marketing rules.

WordPress email (wp_mail)

Uses the mail transport already configured on the WordPress site. Configure authenticated SMTP or a trusted mail service where required by the host. The result from the test email confirms the site accepted the send request; check the recipient inbox and spam folder.

Resend

Requires a valid Resend API key and sender address on a verified sending domain. A newly saved key selects Resend. Use a restricted key where available and protect it as a secret.

Protect the Resend key Prefer defining TDLPW_RESEND_API_KEY in wp-config.php. The settings form can store a key in the WordPress database; limit administrator access and backups accordingly. Never publish a real key in this guide, a screenshot, a support post, or source control.

A provider test email is operational and does not contact the marketing audience. Campaign eligibility and the consent checks still apply when sending marketing messages.

12 · PRIVACY & SECURITY

Know what the site stores and sends

CourseBridge works with account identity, order history, course access, email consent, and campaign delivery. Document these data flows in the site privacy notice and any directory submission.

Data processed by the plugin

  • WordPress user ID, display name, username, and email.
  • Recorded WooCommerce orders, product/course IDs, totals, currency, status, and purchase date.
  • LearnPress enrollment and CourseBridge access dates/status.
  • Marketing opt-in/out status and related timestamps/source.
  • Campaign subject, recipient email, result, provider detail, and send time.

External delivery / licensing

  • Resend: campaign/test recipient details, message subject/content, and sender information are sent to the email provider when Resend is selected.
  • WordPress mail: mail is handed to the transport configured by the site.
  • Taskdrip licensing/updates: the paid build uses a license/update service. Explain its purpose and data flow in the public readme and link applicable service privacy/terms.
  • License terms: administrators can enable monthly, yearly, and lifetime plans and set each price in Plugin Studio. Monthly and yearly renewals are manually approved after payment review; lifetime is a one-time license with no expiry. Plans do not auto-charge.

Privacy controls in the current package

  • Campaign recipients are gated by recorded marketing opt-in; unsubscribe links update the account’s preference.
  • The plugin registers WordPress personal-data export and erasure handlers for course purchases and email preferences.
  • The erasure handler anonymizes retained purchase references/totals and removes associated campaign logs and consent metadata; the site owner should review the wording and retention policy.
  • Deactivation preserves order and course records; deactivation is not equivalent to erasing plugin data.
Admin protection Destructive course actions and settings/campaign submissions require capability checks and nonce verification in the generated code. Keep WordPress, WooCommerce, LearnPress, and administrator accounts secured and updated.

Privacy obligations vary by jurisdiction and site practices. Confirm all data retention, provider terms, transfer, consent, and user-rights statements with the site owner before launch.

14 · WORDPRESS.ORG READINESS

Prepare a directory-safe release

A PDF manual is not the plugin directory submission. The directory expects a complete plugin ZIP and reviewable source, a valid readme, compliant assets, and a release that meets the current guidelines.

Separate the editions before submission The generated CourseBridge LearnpressWOO Connector edition is explicitly described as a licensed paid package and requires an active Taskdrip license. The project release model specifies a useful free core for WordPress.org and a separately distributed paid add-on. Prepare and review the free core; keep premium code out of its directory ZIP. Do not describe the current paid ZIP as already approved or directory-ready.

Package and code checks

  • Ship a complete, human-readable, GPL-compatible directory edition.
  • Keep paid add-on code and keys out of the free directory ZIP.
  • Declare the external licensing/update/email services, data sent, and relevant terms/privacy links.
  • Run Plugin Check and current coding/security checks.
  • Test a clean install and update on staging across claimed versions.

Readme and listing checks

  • Validate the exact readme.txt with the official validator.
  • Use the real WordPress.org contributor usernames.
  • Set Stable tag, Requires at least, Requires PHP, and truthful Tested up to.
  • Use an accurate short description and feature list; avoid unsupported claims.
  • Submit real, current screenshots and captions for the free edition.

Screenshots and listing media

WordPress.org plugin screenshots are typically stored in the SVN repository’s top-level assets/ directory (not inside trunk/assets/). Use numbered names such as screenshot-1.png and matching numbered screenshot descriptions in readme.txt. Capture the actual submitted free edition on a clean WordPress site; do not use these illustrative mock screens as production listing screenshots.

Submission sequence

  1. Finalize the free-core/premium boundary and the license/service disclosures.
  2. Build a release ZIP and test it on a clean staging site.
  3. Prepare the readme, icon/banner, and real screenshots.
  4. Run Plugin Check, readme validation, and any current review tools.
  5. Submit through the WordPress.org plugin developer workflow and respond to review feedback.
  6. Publish only after the plugin has been approved; keep release tags and stable versions synchronized.

Directory rules and asset specifications can change. Recheck the official handbook immediately before submitting. Acceptance is decided by WordPress.org reviewers.
